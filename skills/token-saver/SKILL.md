# 사용량 아끼기

품질이 떨어지면 안 되는 일(실제 화면 확인, 테스트, 돈·보안 판단)은 아끼지 않는다.

## 1. 대화 중에 모델을 바꾸지 않는다
- 대화 도중 모델을 바꾸면 그때까지 쌓인 캐시가 깨져서 앞 내용을 처음부터 다시 읽는다.
- 다른 모델이 필요하면 **서브에이전트나 새 대화에** 그 모델을 지정한다.
  - 찾기·목록 정리·단순 변환 → 작은 모델(haiku·sonnet) 서브에이전트
  - 판단·설계·코드 수정 → 메인 대화

## 2. 생각 강도(effort)는 보통으로, 어려운 단계만 올린다
- 막히는 버그, 설계 결정, 돈·법·보안 판단에서만 올리고, 끝나면 다시 내린다.

## 3. 작은 것부터 시키고, 실패한 것만 큰 걸로
- 반복 작업은 먼저 작은 모델로 돌리고, 틀린 것만 메인 대화가 다시 한다.

## 4. 읽는 양 줄이기
- 큰 파일은 필요한 부분만(줄 범위, 검색). 같은 파일을 여러 번 통째로 읽지 않는다.
- 스크린샷보다 글자로 읽기. 이미지는 꼭 필요할 때만, 작게.
- 긴 출력은 `head`·`tail` 로 자른다.
- Word·엑셀·PDF·파워포인트는 글로 바꿔 읽는다: `pip install markitdown` 뒤 `python -m markitdown "<파일>" -o out.md` → 필요한 부분만 읽기. 내 PC 안에서만 돌아서 회사 자료도 된다.

## 5. 대화 길이 관리
- 주제가 바뀌면 새 대화. 한 대화에 여러 프로젝트를 섞지 않는다.
- 대화가 길어지면 지금까지 한 일·다음 할 일을 메모(프로젝트 CLAUDE.md 등)에 남기고 새 대화로 넘어간다.
- 다른 대화·서브에이전트에 보내는 지시는 짧게, 필요한 것만.

## 6. 하지 않는 것
- 사용량을 아낀다는 이유로 확인 안 된 외부 도구를 설치하지 않는다.
- 검증(실제 화면 확인, 테스트)을 건너뛰지 않는다.

## 점검표 (큰 작업 시작 전 10초)
1. 이 일에 가장 큰 모델이 꼭 필요한가? 아니면 작은 모델 서브에이전트로.
2. 지금 생각 강도가 이 일에 맞나?
3. 통째로 읽어야 하나, 필요한 부분만 읽으면 되나?
4. 이 대화에서 계속해도 되나, 새 대화가 나은가?
