# 회의록 정리

**사용자가 표만 원하거나 할 일만 원해도 3번(JSON 저장)과 4번(검사)은 빼지 않는다.** 검사를 통과한 것만 보여 준다.

회의록에서 제일 위험한 건 **없는 담당자·없는 마감을 그럴듯하게 채우는 것**이다. 그래서 모든 항목에 근거 줄 번호를 달고, `scripts/verify.py` 로 검사한 뒤에만 넘긴다.

## 준비물
- Python 3.9+ (추가 설치 없음).
- 회의 내용이 글(.txt·.md)이어야 한다. 워드·PDF면 먼저 글로 바꾸고(`pip install markitdown` → `python -m markitdown 파일 -o 회의.txt`), 녹음 파일이면 받아쓰기 도구로 글을 먼저 만든다.

## 순서
1. **줄 번호 붙여 읽기**: 원본을 고치지 않고, 줄 번호를 붙여 끝까지 읽는다.
   ```bash
   python -c "import sys;[print(i,l.rstrip()) for i,l in enumerate(open(sys.argv[1],encoding='utf-8'),1)]" "<회의.txt>"
   ```
2. **뽑기** — 규칙:
   - **결정 사항**: "~하기로 해요", "~로 갑니다"처럼 정해진 것만 쓴다. **나중에 뒤집힌 말은 최종 결정만** 쓴다(예: "텀블러로 가죠" → 뒤에서 "보류"면 보류가 결정).
   - **할 일**: 누가·무엇을·언제까지. 담당은 회의에서 그 사람이 맡는다고 한 경우만 쓴다. 농담·가정("제가 할게요, 농담이고")은 빼고 실제로 맡은 사람을 쓴다.
   - **담당·마감이 안 나왔으면 "미정"**이라고 쓴다. 날짜를 계산해 지어내지 않는다. "단가표 받은 다음 날"처럼 조건이면 **말한 그대로** 쓴다.
   - **미정 사항**: 다음으로 미룬 것, 아직 모른다고 한 것.
   - **다음 안건**: 다음 회의에서 먼저 보자고 한 것.
   - 항목마다 근거 줄 번호(`lines`)를 단다. 담당자 이름과 마감 말이 그 줄 안에 실제로 있어야 한다.
3. **JSON 저장**: `<회의 파일 이름>_회의록.json`
   ```json
   {"decisions": [{"text": "...", "lines": [26]}],
    "actions": [{"task": "...", "owner": "이름 또는 미정", "due": "말한 그대로 또는 미정", "lines": [5, 6]}],
    "open": [{"text": "...", "lines": [15]}],
    "next_agenda": ["..."]}
   ```
4. **검사 (빼먹지 말 것)**:
   ```bash
   python "<이 스킬 폴더>/scripts/verify.py" "<회의.txt>" "<회의>_회의록.json"
   ```
   `"ok": true` 가 아니면 `problems` 에 나온 항목을 원문 줄과 다시 대조해 고치고 다시 검사한다. 근거가 없으면 지우거나 "미정"으로 바꾼다.
5. **회의록 문서**: `<회의 파일 이름>_회의록.md` 로 저장하고 사용자에게 보여 준다.
   - 맨 위 한 줄: 결정 N · 할 일 N · 미정 N — 근거 검사 통과
   - `## 결정 사항` (번호 목록, 끝에 `(26행)`)
   - `## 할 일` 표: 담당 | 할 일 | 마감 | 근거
   - `## 미정 사항` · `## 다음 회의 안건`
   - 메일·메신저로 보낼 3줄 요약 (원하면)

## 연습해 보기
`sample/주간회의_1103.txt` (가짜 회사 회의 33줄)로 해 본 뒤 정답과 비교한다.
```bash
python scripts/verify.py sample/주간회의_1103.txt sample/주간회의_1103_회의록.json --expected sample/주간회의_1103.expected.json
```
정답: 결정 3 · 할 일 6 · 미정 2. 함정 2개(뒤집힌 결정, 농담으로 한 "제가 할게요")를 피해야 만점.
